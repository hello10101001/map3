# 드론 수색 GCS — 안드로이드 패드 앱

산불·인명 수색 드론의 구역 분할, 경로 업로드(PX4), 실시간 위치·탐색률, 열화상 탐지 알림을 보여 주는 관제 앱입니다.

```
web/        앱 화면 (HTML 하나). APK에도, 웹(PWA)에도 이 폴더를 그대로 씀
app/        안드로이드 앱 (web/ 를 감싸는 WebView + 위치 권한·파일 저장·화면 켜짐·진동)
bridge/     gcs_bridge.py — PX4 드론 ⇄ 앱 연결 (지상 노트북 또는 패드 Termux에서 실행)
docs/       Firebase 구조 (라즈베리파이 업로더가 따를 형식)
```

---

## 1. APK 만들기

### 방법 A — GitHub에서 자동으로 (PC에 아무것도 설치하지 않아도 됨)

1. github.com 에서 새 저장소를 만듭니다 (비공개 권장).
2. 이 폴더 전체를 올립니다. 웹에서 올릴 때는 **Add file → Upload files** 로 폴더 안 파일을 모두 끌어다 놓으세요.
   `.github` 폴더도 꼭 함께 올라가야 합니다.
   점(.)으로 시작하는 폴더는 컴퓨터에서 숨김 처리되어 빠질 때가 있습니다. 올린 뒤 저장소에 `.github` 가 없으면:
   **Actions** 탭 → **set up a workflow yourself** → `.github/workflows/build-apk.yml` 내용을 그대로 붙여 넣고 **Commit**.
3. 저장소의 **Actions** 탭 → **APK 빌드** 가 자동으로 돌아갑니다 (약 3~5분).
4. 끝난 실행을 눌러 맨 아래 **Artifacts → drone-gcs-apk** 를 내려받으면 압축 안에 `app-debug.apk` 가 있습니다.

### 방법 B — Android Studio

1. Android Studio → **Open** → 이 폴더 선택 (처음 열 때 필요한 SDK를 자동으로 받습니다).
2. 메뉴 **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.
3. `app/build/outputs/apk/debug/app-debug.apk` 가 만들어집니다.

## 2. 패드에 설치

1. APK를 패드로 옮깁니다 (USB, 구글 드라이브, 카카오톡 나에게 보내기 등).
2. 패드의 **파일** 앱에서 APK를 누릅니다.
3. "출처를 알 수 없는 앱" 안내가 나오면 **설정 → 이 출처 허용** 을 켜고 돌아와 **설치**.
4. 처음 실행하면 위치 권한을 묻습니다 → **앱 사용 중에만 허용**.

## 2-1. 수정한 뒤 APK 다시 만들기 (업데이트)

1. 바뀐 파일을 GitHub 저장소의 **같은 폴더**에 올려 덮어씁니다.
   예) `web/index.html` 이 바뀌었으면 저장소에서 `web` 폴더를 연 뒤 **Add file → Upload files** → 파일을 끌어다 놓고 **Commit changes**.
2. 올리면 **Actions** 에서 APK 빌드가 자동으로 시작됩니다 (약 3~5분). 자동으로 안 돌면 **Actions → APK 빌드 → Run workflow**.
3. 초록 체크가 뜨면 그 실행을 눌러 **Artifacts → drone-gcs-apk** 를 받고, 압축을 풀어 `app-debug.apk` 를 패드에 옮겨 설치합니다.
4. 설치 화면에서 **업데이트** 를 누르면 기존 앱 위에 덮어 설치됩니다 — 설정·임무 기록·지난 기록은 그대로 남습니다.

> 앱은 항상 저장소의 `app/debug.keystore` 로 서명되고, 빌드할 때마다 버전 번호가 1씩 올라가서 덮어 설치가 됩니다.
> 이 파일을 지우거나 바꾸면 덮어 설치가 안 되니 그대로 두세요. (이 서명 방식이 들어가기 전에 설치한 앱은 한 번만 지우고 새로 설치해야 합니다.)

## 3. 앱에서 달라지는 점 (브라우저와 비교)

| 기능 | 브라우저(PWA) | 안드로이드 앱 |
|---|---|---|
| 위치 | HTTPS 주소에 올려야 동작 | 바로 동작 (앱이 권한을 직접 받음) |
| 브리지 연결 | 다른 기기면 `wss://` + 인증서 필요 | 같은 Wi-Fi 노트북에 `ws://<IP>:8766` 바로 연결 |
| CSV·GeoJSON 저장 | 브라우저 다운로드 | `다운로드/DroneGCS` 폴더 |
| 화면 꺼짐 방지 | 지원되는 브라우저에서만 | 항상 |
| 뒤로 가기 | 브라우저 뒤로 | 사진 → 시트 → 다른 메뉴 순으로 닫고, 지도에서는 두 번 눌러 종료 |
| 위치 권한 거부 시 | 안내 문구 | ‘앱 설정 열기’ 버튼으로 바로 이동 |

인터넷이 필요한 것: 지도 타일·지형 고도 자료(한 번 받은 지역은 저장되어 오프라인에서도 씀), Firebase.
인터넷 없이 되는 것: 앱 화면, 구역 계산, 경로 업로드·비행 추적(브리지와 같은 Wi-Fi만 있으면 됨).

**지형 고도**: 출발지가 정해지면 주변 지형 자료(AWS 공개 지형 타일, 안 되면 Open-Meteo)를 받아
칸마다 주변 가장 높은 땅보다 설정 고도만큼 높게, 출발지↔구역 사이는 가는 길의 능선보다 설정 고도만큼 높게 날도록 웨이포인트 고도를 정합니다.
상태는 지도 화면 ‘선택 영역 정보 → 지형 고도’에 나오고, 자료가 없으면 평지(출발지 기준 같은 고도)로 계산하며 업로드 때 주의 문구가 뜹니다.
현장에 인터넷이 없으면 출발 전에 인터넷이 되는 곳에서 그 지역을 한 번 열어 두세요.
지형 자료(약 30m 해상도)에는 나무·건물·송전탑 높이가 다 들어 있지 않으니 비행 고도는 여유 있게 잡으세요.

**비행 시간 계산**: 이륙 상승·착륙 하강(사양의 상승·하강 속도, PX4 기본 3·1.5m/s), 꺾을 때 감속·가속, 칸 사이 고도 변화까지 넣어 계산합니다.
지도 화면 ‘현장 바람’에 풍속과 불어오는 쪽을 넣으면 맞바람·뒷바람·옆바람에 따른 대지 속도로 다시 계산합니다 (비행 속도의 70% 이상이면 경고).

**출발지**: 앱을 켜면 지도는 내 위치로 가지만 출발지와 격자는 만들지 않습니다. ‘내 위치로 설정’(실시간이면 ‘드론 GPS로 설정’)이나
‘지도에서 지정’을 눌러 출발지를 정하면 그때 영역과 격자를 만듭니다.

**영역 그리기**: ‘영역 그리기’를 누른 뒤 지도를 끌어 사각형 영역을 만듭니다. 끄는 동안 나오는 숫자는 손을 뗀 뒤 패널과 같은 계산입니다:
한 번에 돌 수 있으면 ‘한도의 N%’(가장 많이 일하는 드론 기준), 못 돌면 ‘한도 초과 · N회 비행’.

**재촬영 (여러 칸 한 번에)**: 임무가 끝나면 지도 아래 가운데에 재촬영 막대가 뜹니다. ‘칸 고르기’를 누르고 지도에서 칸을 누르면 골라지고(파란 칸 + ✓), 다시 누르면 빠집니다. 막대에 필요한 드론 수와 예상 시간이 바로 나오고, 같은 자리의 ‘재촬영 시작’을 누르면 고른 칸만 한 번 비행으로 다시 찍습니다. 드론은 한 번 비행 한도 안에서 가장 적은 수만 쓰고, 칸 하나는 반드시 드론 한 대가 맡으며, 드론마다 다른 방향의 칸을 맡습니다. 한 번 비행으로 다 못 찍으면 칸을 줄이라고 알려 줍니다.

**재촬영한 칸**: 재촬영을 마친 칸은 지도에 파란 테두리와 왼쪽 위 ‘재촬영’ 글자로 표시되고, 기록을 다시 불러와도 남습니다.

**글자 크기**: 설정 → ‘글자 크기’에서 작게 · 보통 · 크게 · 아주 크게 · 최대 중에서 고릅니다. 버튼·글자·지도 위 표시가 함께 커지고, 다시 켜도 유지됩니다.

**내보내기 (탐지 결과 화면)**: ‘탐지 결과 CSV’(탐지 지점 목록), ‘격자 평균 온도 CSV’(칸별 평균 온도)는 엑셀·구글 시트에서 열고, ‘수색 구역·경로 GeoJSON’(출발지·칸·경로·탐지 지점)은 QGIS나 geojson.io 같은 지도 프로그램에서 엽니다. 파일은 기기의 다운로드 폴더에 저장됩니다.

**비행금지구역 (자동)**: 설정 → ‘공식 비행금지구역’에 브이월드 인증키를 넣으면, 출발지가 정해질 때 주변 약 15km의
비행금지구역·비행제한구역·관제권·군작전구역을 국토교통부 공역 자료(브이월드 2D 데이터 API)에서 받아 지도에 표시합니다.
받은 구역은 기기에 저장되어(7일마다 새로 받음) 인터넷이 없는 현장에서도 보입니다.
- 인증키: vworld.kr 회원가입 → 인증키 발급(무료, ‘2D 데이터 API’). 발급할 때 적은 서비스 URL을 앱의 ‘서비스 URL’ 칸에도 똑같이 넣습니다.
- 찍을 칸이나 드론이 오가는 경로가 구역과 겹치면 패널 목록에 표시하고, 임무 시작 전에 한 번 더 묻습니다 (군작전구역은 주의 표시만).

**승인서로 구역 풀기**: 패널 목록의 ‘승인서 등록’(또는 지도에서 칸 밖의 구역을 누름)에서 드론원스톱에서 받은 비행 승인서(사진·PDF),
승인번호, 승인 기간을 넣으면 그 기간 동안만 그 구역 경고를 끄고 지도에 초록색으로 표시합니다. 서류는 기기 안에만 저장됩니다.
앱은 서류 내용을 확인하지 못하므로 승인받은 고도·시간·범위는 운영자가 지켜야 합니다.
임시 비행금지(항공고시보), 고도 150m 초과, 사람이 많은 곳 비행처럼 지도 자료에 없는 제한도 있으니 드론원스톱에서 함께 확인하세요.

**비행 중 경고**: 남은 배터리가 복귀에 빠듯하거나 예비 배터리 아래로 떨어질 때, 실시간 드론 위치가 끊길 때, 브리지 연결이 끊길 때
지도 위 빨간 막대·진동·알림으로 알립니다.

**지도 위 온도 열지도**: 지도 왼쪽 온도계 단추를 누르면 칸마다 찍은 사진의 평균 온도를 색으로 칠하고(파랑=낮음, 빨강=높음), 칸 왼쪽 아래에 평균 온도 숫자를 씁니다. 칸이 화면에서 너무 작으면 숫자는 지도를 확대할 때 나옵니다.

**탐지 위치 공유**: 탐지 결과 화면의 ‘공유’(한 건) 또는 ‘전체 공유’로 좌표·온도·카카오맵/구글 지도 링크를 문자·카카오톡 등으로 보냅니다.

**현장용 지도 미리 받기**: 설정 → ‘현장용 지도 미리 받기’에서 지금 지도 화면(그린 수색 영역 포함) 범위의 위성 지도와 지형 고도를
여러 확대 단계로 받아 둡니다 (최대 3000장, 약 60MB). 받은 지도는 지우기 전까지 남고, 통신이 없는 현장에서도 그대로 보입니다.

## 4. 브리지 (PX4 드론 연결)

`bridge/gcs_bridge.py` 맨 위 설명을 참고하세요. 요약:

```
pip install pymavlink
python3 bridge/gcs_bridge.py --mav udpin:0.0.0.0:14550        # 실기체
python3 bridge/gcs_bridge.py --demo --lat 33.4996 --lng 126.5312   # 시험용 데모 드론
```
앱 → 설정 → 드론 연결 → **실시간** → 주소 `ws://<노트북 IP>:8766` → **연결**.

**비밀번호**: 같은 Wi-Fi의 아무 기기나 드론에 명령을 보내지 못하게 브리지를 `--token 비밀번호`(또는 환경 변수 `GCS_BRIDGE_TOKEN`)로 켜고,
앱 설정의 ‘브리지 비밀번호’에 같은 값을 넣으세요. 틀리면 브리지가 연결을 끊고 앱은 다시 시도하지 않습니다.

### 4-00. 라즈베리파이에 다 넣기 (추천) — `pi/README.md`
드론의 라즈베리파이에서 mavproxy 중계 · 브리지 · 카메라(실시간 영상·임무 사진·열화상 탐지)가 자동으로 켜지게 설치합니다 (`pi/install.sh`).
앱은 `ws://<파이 IP>:8766`에 연결하고, 지도의 칸을 누르면 그 칸의 사진·열화상 사진을 봅니다.

### 4-01. 노트북 브리지 — 드론 ─ 텔레메트리 ─ 노트북 ─ Wi-Fi ─ 태블릿
```
드론: 픽스호크 TELEM1 ─ 텔레메트리 무선기          TELEM2 ─ 라즈베리파이 (카메라·열화상, pi_camera.py)
                         ⇅ 무선 (1~2km)                         ⇅ Wi-Fi (닿을 때: 이륙 전·착륙 뒤)
노트북: 무선기(USB, COM3) ─ gcs_bridge.py ──────────────────────┘
                         ⇅ Wi-Fi (같은 공유기 또는 노트북 핫스팟)
태블릿 앱  (+ 노트북 QGroundControl도 같은 무선기로 같이 사용)
```
1. 노트북에 Python 3를 설치하고, `bridge/laptop_bridge.bat`을 메모장으로 열어 `COM`(장치 관리자 → 포트에서 무선기 번호), `PI`(파이 주소), `TOKEN`(비밀번호)을 고친 뒤 더블클릭합니다. 처음 한 번 `pymavlink`·`pyserial`을 자동으로 설치합니다.
   - 직접 실행: `python gcs_bridge.py --mav COM3,57600 --pi http://dmdpi.local:8080 --qgc udpout:127.0.0.1:14550 --token 비밀번호`
   - Windows 방화벽 창이 뜨면 **허용**(개인 네트워크)을 누르세요. 안 그러면 태블릿이 노트북에 못 붙습니다.
2. 앱: 설정 → 드론 연결 → 실시간 · **브리지 · Wi-Fi** → 주소 `ws://<노트북 IP>:8766` (배치 파일 창에 IP가 나옴) · 비밀번호 → 연결.
3. 동작
   - 위치·배터리·경로 업로드·이륙·복귀: 텔레메트리 무선기로.
   - 경로를 올리면 노트북 브리지가 파이에 임무 정보를 보냄 → 파이가 수색 구역에서 사진을 찍음. **경로는 이륙 전, 파이 Wi-Fi가 닿을 때 올리세요** (못 보내면 앱에 안내가 뜸).
   - 비행 중 열화상 탐지: 파이 → 픽스호크 → 무선기 → 노트북 → 앱으로 바로 알림 (PX4 `MAV_0_FORWARD = 1`, `MAV_1_FORWARD = 1` 필요).
   - 사진·열화상 사진·탐지 사진: 파이 Wi-Fi가 닿으면(착륙 뒤 등) 노트북이 5초마다 받아 와 앱에 보냄. 칸을 누르면 그 칸의 사진과 열화상이 나란히 보임.
   - QGroundControl: 노트북에서 켜면 UDP 14550으로 자동 연결 (무선기를 같이 씀).
4. 파이: `pi/README.md`대로 설치하되 `config.env`에서 `QGC_OUT=""`(QGC는 노트북 무선기로 봄), `TOKEN`은 노트북과 같게. 파이의 `drone-bridge`는 안 써도 됩니다 (`sudo systemctl disable --now drone-bridge`).

### 4-0A. 텔레메트리 무선기를 태블릿에 바로 꽂기 (노트북·브리지 없이)
지상용 텔레메트리 무선기(SiK 등)를 태블릿 USB(OTG 젠더)에 꽂으면 앱이 직접 MAVLink로 드론과 통신합니다.

```
태블릿 앱 ─ USB ─ 무선기 ⇄ (무선, 보통 1~2km) ⇄ 무선기 ─ 픽스호크 TELEM1
                                                      └ TELEM2 ─ 라즈베리파이 (촬영·탐지)
```
- 앱: 설정 → 드론 연결 → 실시간 · 연결 방식 **텔레메트리 무선기** · 무선기 속도(SiK 기본 57600) → 연결. 처음 한 번은 USB 사용 허용 창이 뜹니다.
- 무선기로 오가는 것: 위치·배터리·비행 모드, 경로 업로드, 이륙, 복귀, PX4 안내 문구, **라즈베리파이의 탐지 알림**.
- 사진은 무선기로 보내기엔 너무 커서 **파이 Wi-Fi**로 받습니다. 연결 칸의 ‘파이 Wi-Fi 주소’에 `ws://10.42.0.1:8766`(파이 핫스팟)을 넣어 두면, 태블릿이 파이 Wi-Fi에 닿을 때(보통 착륙 뒤) 10초마다 확인해 칸 사진·칸 평균 온도·탐지 사진을 받아 옵니다. 파이에서는 브리지를 `--local`로 켜 둡니다 (아래 4-0).
- 탐지 알림 형식: 라즈베리파이가 STATUSTEXT 한 줄 `DET <번호> <위도> <경도> <온도>`를 MAVLink로 보냅니다 (예: `DET d17 33.4512345 126.5712345 36.8`). 번호는 `detections.jsonl`의 `id`와 같게 → 나중에 Wi-Fi로 받은 사진이 같은 탐지에 붙습니다.
- PX4 설정: 무선기 포트(TELEM1 = `MAV_0_`)와 파이 포트(TELEM2 = `MAV_1_`) 모두 `MAV_0_FORWARD = 1`, `MAV_1_FORWARD = 1`(메시지 중계)을 켜야 파이의 탐지 알림이 무선기로 넘어갑니다. 무선기 포트(TELEM1)는 기본값 그대로.
- 노트북에 무선기를 꽂아 쓰는 것도 됩니다: `python3 gcs_bridge.py --mav /dev/ttyUSB0,57600` (윈도우는 `COM3,57600`) → 앱은 브리지 방식으로 연결. 브리지도 `DET` 알림을 탐지로 바꿔 앱에 보냅니다.
- 무선기 주파수가 국내에서 쓸 수 있는 대역인지 꼭 확인하세요.

### 4-0. 인터넷 없이 Wi-Fi로 (드론 1대)
태블릿을 드론 라즈베리파이의 핫스팟 Wi-Fi에 바로 연결합니다. 위치·명령뿐 아니라 **탐지 알림(열화상 사진 포함)과 칸 사진도 Wi-Fi로** 받습니다.

```bash
# 파이에서 (한 번만) 핫스팟 만들기 — 파이 주소는 10.42.0.1
sudo nmcli device wifi hotspot ssid DRONE1 password 8자이상비밀번호
# 픽스호크 시리얼 하나를 브리지와 촬영 프로그램이 같이 쓰도록 나눔
mavlink-routerd -e 127.0.0.1:14550 -e 127.0.0.1:14540 /dev/serial0:921600
python3 gcs_bridge.py --mav udpin:127.0.0.1:14550 --local /home/pi/drone-data/local --token 비밀번호
python3 pi_drone.py --config config.json --local /home/pi/drone-data/local --mav udpin:127.0.0.1:14540
```
앱: 설정 → 드론 연결 → 실시간 · 연결 방식 **브리지 · Wi-Fi** → 주소 `ws://10.42.0.1:8766` · 같은 비밀번호 → 연결.

- 경로를 올리면 브리지가 `--local` 폴더에 `mission.json`(임무 번호·칸 격자·촬영 간격·경로)을 쓰고, 촬영 프로그램이 이를 보고 찍습니다.
- 촬영 프로그램이 `out/<임무>/photos.jsonl`·`detections.jsonl`에 한 줄씩 쓰면 브리지가 바로 앱에 알립니다. 칸을 누르면 사진을 파이에서 바로 받아 봅니다.
- 앱이 잠깐 끊겼다 다시 연결되면 그동안 생긴 탐지를 다시 받습니다.
- Wi-Fi는 보통 수백 m까지만 닿습니다. 드론이 멀리 가면 화면이 멈추지만, 브리지가 파이 위에 있어 임무 비행은 계속됩니다. 돌아오면 다시 이어집니다.
- 파이 없이 시험: `python3 gcs_bridge.py --demo --drones 1 --local ./local --token pw` 와 `python3 bridge/local_test_pi.py ./local` 을 함께 켜면 가짜 사진·탐지가 앱에 들어옵니다.

### 4-1. Firebase로 연결 (브리지 없이 드론 LTE 직접)

드론의 라즈베리파이에서 `drone_agent.py`(drone-firebase 묶음)가 돌고 있으면, 앱 설정 → **연결 방식 → Firebase (드론 LTE 직접)** 를 고르고
오른쪽 Firebase 칸에서 운영자 계정으로 로그인하면 됩니다. firebaseConfig에 Realtime Database의 `databaseURL`이 있어야 합니다.
업로드·이륙·임무 종료(복귀)·위치·PX4 메시지가 브리지와 똑같이 동작하며, 점마다 지형 고도·이륙 고도·촬영 구간도 함께 보냅니다.
Firebase 프로젝트·계정·보안 규칙 설정은 drone-firebase의 README를 따르세요.

## 5. Firebase 사용 시 확인

- API 키에 웹사이트 제한을 걸었다면 `https://appassets.androidplatform.net` 를 허용 목록에 추가하세요 (앱이 이 주소로 동작합니다).
- 이메일/비밀번호 로그인을 쓰려면 Firebase 콘솔 → Authentication 에서 켜 두세요.
